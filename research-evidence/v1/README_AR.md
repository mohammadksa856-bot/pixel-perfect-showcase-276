# WEB-08B01 — عقد الادعاء والدليل البحثي v1

الحالة: تنفيذ محلي مستقل ونموذج اصطناعي؛ ينتظر مراجعة مستقلة على SHA ثابت. لا اعتماد مستخدم نهائي أو تفعيل إنتاجي.

## المرجع والحدود

- الأصل الهندسي WEB-07: `d7d88c19fee626346b12d961f3a539fc31423f1f`.
- تدقيق WEB-08A: `b037ecb7be41661243ccf5f68b4d536f8e23aedd`؛ المصفوفة والمصادر والاشتقاقات التسعة مقروءة ومستخدمة كمتطلبات.
- الملفات الجديدة تحت `research-evidence/v1` فقط؛ ليست مستوردة من التطبيق، ولا تعدّل المحرك أو القيم أو Supabase أو أعلام الإنتاج.
- العقد معرفات ونسخ وبصمات وإسناد وحالات؛ لا يحمل حقل `value` ولا درجة جاهزية. النص البحثي ليس مصدرًا عدديًا موازيًا، ويحتاج مراجعة ادعاءاته.
- جميع القيم والهويات والموافقات والشهادات في `synthetic.ts` **اصطناعية صريحة**، والبصمات المتكررة فيها قيم اختبارية للشكل، لا بصمات مستندات مالية حقيقية.

## 1. النموذج وإصداراته

`ClaimSchema` في `contract.ts` هو العقد التنفيذي الصارم `research-claim/1`، مع types مشتقة منه. الحقول غير المعلنة مرفوضة؛ لا تحويل حقول عينة إلى موافقة ضمنية.

| الحقل                              | الغرض                                                                                               |
| ---------------------------------- | --------------------------------------------------------------------------------------------------- |
| `claimId/revision/supersedes`      | معرف مستقر ونسخة غير قابلة للاستبدال؛ سجل النسخة السابقة محفوظ                                      |
| `topic`                            | مفتاح واحد من موضوعات المستثمر الأصلية الـ18، وليس فئة تشغيلية                                      |
| `contentKind`                      | حقيقة منشورة / رقم مشتق / تفسير بحثي / افتراض / سيناريو                                             |
| `temporalBasis`                    | بيانات فعلية / توجيه مُصدر / تقدير محلل / افتراض؛ لا تحويل التوجيه لتاريخ فعلي                      |
| `company`                          | السوق والرمز وهوية الكيان؛ القطاع `null` إذا لم يوجد إثبات، وإلا تصنيف ومخطط وإصدار ودليل           |
| `identity`                         | المقياس والكيان ونطاق التجميع والأبعاد ونوع الفترة وبدايتها ونهايتها والسنة/الربع والوحدة والعملة   |
| `body`                             | نص ولغة؛ ليس قيمة مالية بديلة؛ يحتاج تحريرًا ومراجعة                                                |
| `sources`                          | رابط HTTPS آمن، معرف مستند وإصدار وSHA256 وتاريخ نشر وصفحة أو جدول أو anchor                        |
| `bindings`                         | مرجع حقيقة `id/version/sha256` ودورها output/input/context وهويتها المتوقعة ودليلها                 |
| `calculation`                      | معرف منهج وإصداره ومراجع ناتجه ومدخلاته فقط؛ لا تعبير مالي يُنفذ في React                           |
| `rights`                           | حالة معلنة ومراجع منح حقوق بإصداراتها؛ القرار يتحقق من سجل خادم موثوق، لا يصدق الحالة المعلنة وحدها |
| `authorId/createdAt`               | صاحب النسخة وزمن تأليفها                                                                            |
| `informationPublishedAt`           | تاريخ إتاحة المعلومات المستند إليها؛ لا يجوز أن يسبق مصادرها أو يتجاوز زمن تأليفها                  |
| `validFrom/validUntil/limitations` | صلاحية التحليل وحدوده؛ نهاية نافذة الصلاحية غير مشمولة                                              |

تواريخ الفترات `YYYY-MM-DD` صالحة تقويميًا؛ الطوابع الزمنية UTC بصيغة ثابتة ذات ثلاث خانات للميلي ثانية. لا نقل صامت ليوم غير موجود أو اختلاف offsets عند المقارنة. الهوية تقارن النوع والبداية والنهاية والعملة والوحدة والنطاق والأبعاد، لا تاريخ النهاية وحده. التواريخ المالية لا تفترض سنة ميلادية للشركة أو تعيد تعريف تقويم المُصدر.

أي تعديل محتوى أو هوية أو مرجع أو حقوق يغيّر بصمة النسخة. تُنشأ نسخة جديدة، ولا يُعدّل السجل المنشور أو سجل مراجعته السابق. التغييرات الكاسرة تحتاج `research-claim/2` أو مهاجرًا صريحًا؛ لا قبول حقول v2 بصمت. canonical encoding يرتب المفاتيح بترتيب ثابت؛ hash إثبات اتساق وليس توقيع مصادقة.

## 2. حالات مستقلة وليست درجة واحدة

`evaluate` يعيد:

- الوجود: `present / unavailable / withheld`.
- الأهلية التقنية: `eligible / ineligible`.
- التحقق المالي للادعاء: `verified / rejected / unreviewed`.
- التحرير: `approved / unreviewed`.
- الحقوق: `permitted / blocked`.
- سير العمل: `Draft / FinanciallyReviewed / EditoriallyApproved / Invalidated / Withdrawn`.
- أهلية انتقال المحتوى: `eligible / blocked` مع الأسباب.

الوجود لا يساوي التأهيل، والتأهيل لا يساوي تحققًا ماليًا أو إجازة تحريرية. أهلية انتقال المحتوى لا تعني نشره أو موافقة المستخدم على الإنتاج. بوابات المصنع الـ18 و95% لا تُقرأ ولا تتغير في هذا العقد.

## 3. انتقالات المراجعة

`appendReview` يضيف حدثًا ولا يعدّل السابق. لكل حدث معرف وهوية مراجع وتاريخ وبصمة تقرير ودليل النسخة وبصمة الحدث السابق. السجل **لكل نسخة ادعاء**؛ نسخة جديدة تبدأ سجل مراجعة جديدًا وتشير إلى سابقتها.

1. Draft → FinanciallyReviewed: أهلية تقنية، أدلة أصلية مؤهلة، تحقق مستقل للحقائق الداخلة، ومراجع مالي غير المؤلف. لكل تحقق مالي هوية وطريقة وتاريخ وبصمة تقرير. لا تكفي نتيجة القارئ أو موازنة القوائم.
2. FinanciallyReviewed → EditoriallyApproved: مراجع تحرير مخوّل، غير المؤلف وغير المراجع المالي في سياسة v1؛ ترتيب الأحداث وتواريخها صحيحان. تشمل المراجعة الفصل بين رأي الباحث وبيان الشركة والافتراض.
3. تغيير إصدار حقيقة/مستند أو الحجب أو سحب التحقق يُبطل الأهلية الحالية؛ نفس القيمة العددية في مستند معاد إصداره لا ترث الموافقات.
4. السحب حدث محفوظ، يمنع إعادة إحياء النسخة بالسجل نفسه. تعديل الرأي يحتاج نسخة ومراجعة جديدتين. `validUntil` يمنع العرض بعد انتهاء الصلاحية.

الأحداث والأدوار ومنح الحقوق تأتي من **resolver خادم موثوق**. ليس هناك endpoint عام لقبول هذه البيانات من المتصفح. سلسلة hashes ليست توقيعًا، ولا تنفذ مصادقة أو RBAC أو حيازة تقارير مراجعة حقيقية. مخزن append-only دائم، تحقق توقيعات/صلاحيات وهوية المراجعين وإبطال الحقوق متطلبات ربط حي لاحقة، وليست ادعاءً منجزًا في PoC.

## 4. التعارض وإعادة العرض والزمن

- يطابق المرجع معرف الحقيقة ونسختها وبصمتها، ثم كل عناصر هويتها ومصدرها وصفحتها/جدولها. لا اختيار لأقرب تاريخ أو أول صف.
- أكثر من قيمة دلالية نشطة مؤهلة للحقيقة نفسها يحجب الادعاء؛ اختلاف رابطين وحده مع معنى وقيمة متطابقين ليس تعارضًا مخترعًا.
- `supersedes` صريح؛ إصدار جديد لا يُستنتج من ترتيب المصفوفة. المستند المعاد إصداره يبطل إسناد القديم في قياس يسمح تاريخ النشر فيه بالإصدار الجديد.
- `asOf` حد معرفة البيانات، و`evaluatedAt` زمن تشغيل صلاحية التحليل والمراجعات والحقوق. ظهور مستند لاحق لا يحقنه في إعادة قياس فترة أقدم؛ المراجعات نفسها لا يجوز أن تأتي من مستقبل زمن التشغيل.
- التوجيه المنشور اليوم قد يخص فترة مستقبلية إذا صنف `issuer_guidance` ومصدره مُصدر؛ لا يُعرض كبيان فعلي. تقدير المحلل يتطلب مصدرًا من نوع analyst. الافتراض/السيناريو لا يعاد تصنيفه حقيقة.
- مصادر أو مدخلات مفقودة أو محجوبة أو غير معروفة الإصدارات لا تُستبدل بقيم WEB-07 المجمدة.

## 6. التوافق الحالي مع المحرك وWEB-07

`legacyWEB07Compatibility()` يعيد `readyForLiveResearchClaims=false` صراحةً. مفاتيح الموضوع والمقياس والوحدة ورابط المصدر ونوع/نهاية الفترة قابلة للاستعمال كعرض، لكن `ValueCell` لا يوفّر جميع المراجع المستقرة وبدايات الفترات والنطاقات وإصدارات المستندات وبصماتها والحقوق وشهادات التحقق. لا نولد IDs من URL أو القيمة أو موضع الصف أو بصمة JSON المعاينة.

`ResearchResolver` منفذ قراءة للمراجع فقط، ليس مخزنًا ماليًا ثانيًا. التطبيق النهائي سيحل المعرفات من المحرك/خدمة الأدلة المصرح بها. هذه الدفعة لا تضيف API أو migration للمحرك. أي فشل في port يظل فشلًا مغلقًا.

روابط Intelligence متوافقة مع `topic/focus` الحاليين. رابط Marefa Data يختار المجموعة المناسبة، لكن مساره الحالي يقبل `tab/open` ولا يثبت fact version/period. لذلك `exactMarefaRowSelectionSupportedByWEB07=false`؛ لا نعلن اكتمال ربط حي دقيق. هذا ليس تراجعًا في WEB-07 المقبول، بل تبعية للعقد الجديد.

## 7. Proof of Concept

```text
bun test research-evidence/v1
bun x tsc -p research-evidence/v1/tsconfig.json --noEmit
bun research-evidence/v1/poc.ts
```

الرحلة المحلية: `http://127.0.0.1:4451/intelligence` → `/evidence` → `/marefa-data?id=…&version=…&sha256=…`.

هذا **محاكي مستقل لمسار الربط**، لا تعديل أو تفعيل لمكونات WEB-07. القيمة الاختبارية لا توجد في claim أو trail؛ تظهر فقط من خدمة البيان الأصلي الاصطناعية عند تطابق المرجع كاملًا. الإصدار الخاطئ 404، والحجب يمنع الدليل/الرابط ولا يكشف القيمة. HTML escaped، وCSP يمنع scripts والنماذج، والخادم GET فقط وloopback وno-store/noindex. ليس نشر Vercel ولا محتوى عامًا ولا شهادة مالية.

فُحص المسار فعليًا عبر Chrome. فشل الوصول الأول كان قيد مقابس الشبكة في بيئة التنفيذ، ثم عمل الخادم على loopback بصلاحية محلية؛ لم نغيّر حماية أي نشر أو أسرار. راجع سجل الاختبارات للفصل بين اختبارات العقد، انحدار WEB-07، وفحص المتصفح.

## 8. المخاطر المتبقية والقبول

- يلزم حل مراجع موثوق من المحرك ومخزن وثائق أصلي وحقوق فعلية؛ لم نصل لبيانات حية.
- يلزم تخزين مراجعات دائم ومصادقة وأدوار ومراجع مخوّلون؛ الهويات الحالية اصطناعية.
- لا يمكن للمخطط التحقق آليًا من صدق نص استثماري أو انتماء تصنيف أو صحة منهج مالي؛ هذه مسؤولية مراجعة الدليل والنص.
- لا DCF أو توقعات أو أسعار أو شهادة اكتمال N02/95% أو قبول مستخدم نهائي أو ترخيص إنتاجي.
- قرار القبول الهندسي يصدر في جلسة Codex مستقلة على SHA ثابت، لا من نجاح اختبارات المؤلف وحده.
